# 自动转写与核对

适用于视频链接、本地音视频、SRT/VTT、已有逐字稿。按用户范围完成“取得原稿 → 文字校订 → 对照证据 → 保存结果”。用户只要原字幕时只提取；只有明确要求成稿、润色或摘要时才另写文章。

用户要求“转写并核对”“核对原音”时，取得原媒体后运行 [本机原音双引擎流程](audio-runtime.md)。这会实际读取声音并生成两份独立识别结果，不要只运行文字差异脚本就交付。已有转写作为候选稿参与比较，不作为模型提示。默认完成机器复核，不要求用户逐句人工听审；仅把机器仍无法消除的分歧列为待确认。

## 取得真实原稿

- 确认来源与范围，优先复用当前任务已有的完整字幕或转写。核对视频编号、标题、作者及开头和结尾；摘要、分享文案、试读片段不能当全文。
- 区分说话内容和画面文字：前者用字幕轨或语音识别，后者提取画面字幕；说明字幕轨是否自动生成。两者不一致时分别记录，不能互相冒充。
- 有可用字幕轨先抽取；没有时使用当前可用、已授权的转写服务或本地 ASR。平台页面失败后切换可用路径，不反复请求同一失败页面。工具选择和命令见 [转写工具与来源](transcription-tools.md)，仅需配置或切换工具时读取。
- BibiGPT 是曾成功处理抖音的路径：提交分享链接 → 验证结果对应原视频 → “字幕脚本” → “阅读全文／原文细读” → “口播逐字稿”。较早界面也在导出弹窗的 Markdown 预览提供全文；以当前页面为准。超时先查结果，避免重复提交。
- 本地先检查音轨、字幕轨及媒体总时长。末条字幕结束早于视频结束不自动表示缺失，需判断尾部是否还有讲话。只取得片段时明确起止位置，不标记完整。
- 将取得的原始字幕／转写原样保存为 `原名_raw.srt`、`.vtt` 或 `.txt`。保留真正的时间码和已有说话人标记；纯文本不虚构时间戳。不要覆盖原稿。

## 文字校订

- Codex 可以直接校订已取得的文字，无需为了这一步另配 LLM API。长稿按语义段处理并保留上下文，最后检查跨段接续、重复和遗漏；不要每次重新生成整条视频转写。
- 修复识别造成的错别字、同音字、标点和断句，保持原意、说话顺序与真实重复。不要把不通顺口语改成作者没说过的句子。原始材料本身的事实错误与识别错误分开记录。
- 对人名、专业词、数字、单位、否定词及影响句意的修改重点查证。明显标点调整可直接完成；缺少声音或画面依据的词语修改标为“上下文推定”，存在多个合理读法则保留疑点或使用 `[不清楚]`，不要悄悄定稿。
- 默认另存 `原名_校订稿.md`，把来源、方法、覆盖范围、核对状态写在文首。用户需要字幕文件时另存 `_corrected.srt/vtt`，文本校订阶段保持原有时间轴；重新断句或调时需另记原因。

## 对照证据，准确标注核对程度

| 实际做过的工作 | 可使用的状态 |
|---|---|
| 仅检查转写文字和上下文 | 文字已校订，未核对原音 |
| 本地两个独立引擎读取原音并比较 | 原音双引擎机器复核完成，标明范围和剩余分歧；不称人工听审 |
| 实际读取指定画面字幕 | 已对照画面字幕，标明范围；不等同原音一致 |
| 使用实际可用的音频理解能力或用户听审证据核实原音 | 已核对原音，标明核实的具体范围 |

- 优先核对疑句和会改变含义的修订，保留前后语境；用户要求全稿听审时覆盖全稿。只有实际具备并使用音频理解能力时才能声称听过；下载文件、播放按钮、波形或 ASR 结果都不是已经听审的证据。
- 默认通过本机脚本处理已有原媒体，原音机器复核已接入，无需另寻付费听审服务。脚本自动保存疑点音频；需要更多前后语境时用 `--start`、`--duration` 重新核验局部。若取不到原媒体，才退回文字校订，明确具体缺口；不得声称已完成原音机器复核。
- 当前可用工具、账号、网络和额度在每次任务中核实；历史成功不代表服务一直可用。沿用已有授权，不重复索要许可；新的私人媒体上传或付费行为需有对应授权。

## 自动检查与交付

- 原稿已有文件时，在工作目录保留一份同格式、仅含正文的校订版，再执行 [差异检查脚本](../scripts/transcript_diff.py)：`python transcript_diff.py raw.srt corrected.srt --output diff.json`，将路径替换为实际绝对路径。它自动列出文字变化、检查字幕条目与时间轴变化；纯文本按行比较，不生成时间码。输出需使用新文件名，格式错误或返回非零时先排查，不能把失败报告当作通过。脚本只核对结构与差异，不能判断字词是否符合声音。
- `python` 是命令示意；若不在 PATH，优先通过 Codex 的 `load_workspace_dependencies` 工具查找已有 Python。PowerShell 用 `& '解释器绝对路径' '脚本绝对路径' ...` 调用，不为运行此标准库脚本另装 Python。
- 对差异报告中的删除、插入、时间漂移逐项解释，排除误漏。为了便于阅读生成的 Markdown 另行检查正文覆盖范围；不要把报告自身的元信息与原稿正文混在一起比较。
- 默认交付校订稿，并在同一文件末尾附简短修改记录：`时间／段落 | 原文 → 校订 | 依据 | 待核对项`。原稿和机器差异报告作为附件保留；短内容可直接在聊天中呈现。
- 重大修订必须能追溯到原稿和对应证据；不要用“已校对”掩盖未取得原音的事实。后续问答先读已保存的稿件，仅对新增疑点返回原媒体。
